Purpose
This figure separates what the local prototype implements and checks from what is implemented but has no completed live public-company execution, what remains held, and what is explicitly outside scope. It does not claim production security, multi-user operation, cloud deployment, completed live research, user benefit, or empirical effectiveness.

Status key
1. IMPLEMENTED AND CHECKED. The repository contains implementation and local test or static-validation evidence for the named boundary. This does not imply production readiness.
2. LIVE UNRUN. Guarded mechanics and fake, synthetic, or adversarial tests exist, but a live public-company execution is not claimed.
3. HELD. Direct live use is not admitted under the current source policy.
4. EXPLICIT NON-GOAL. The capability is deliberately absent from the bounded dissertation prototype.

Reading order and architecture

1. Local entry and container set-up: local-machine and single-user boundary.
   - The loopback browser enters the Next.js control room. A server-side route proxies requests to the private FastAPI service; the browser does not connect to FastAPI or hold its CSRF credential.
   - The CLI covers database initialisation, import, workflow, review, export, evaluation and local serving through the same Runtime/service construction rather than a separate domain path.
   - Docker Compose runs two services. Only the Next.js `app` service is published, at `127.0.0.1:${PORTFOLIO_PORT:-8000}:3000`; the `api` service is exposed only on the private Compose network. Both container roots are read-only and drop Linux capabilities. The API alone mounts `portfolio-state` read/write at `/app/var`. These are local configuration and test facts, not production-deployment evidence.

2. Dashboard, private API and shared task boundary: built and locally tested.
   - Next.js is the sole maintained dashboard. Its same-origin proxy calls FastAPI JSON endpoints and the approved-deck download surface through `PORTFOLIO_API_ORIGIN`.
   - FastAPI checks the exact Host and client boundary, supplies security headers and validates its double-submit CSRF contract. The server-side proxy performs the handshake and attaches the private credentials; neither mechanism is production authentication.
   - API routes and CLI commands delegate to shared Runtime services: `PortfolioImporter`, `PortfolioWorkflow`, `ReportService`, `SourceRegistry`, `CompanyIntakeService`, and, only when cumulative gates pass, `CompanyResearchService`.
   - The service boundary owns typed ingestion and identity, bounded workflow, independent verification, versioned reports, named approval and export decisions. The optional company-research service is implemented, but a live public-company run is not claimed.

3. Local storage and write-once file boundary: built and locally tested.
   - SQLAlchemy sessions persist metadata, provenance, audit, task, verification, report, review, and export state in local SQLite.
   - Application startup runs Alembic to head; the migration schema is checked against the SQLAlchemy metadata model.
   - Create-once or manifest-bound local files live in ignored `var/raw`, `var/sources`, and `var/exports` directories. Hashes support integrity and provenance; they do not establish truth, authority, encryption, anonymisation, or lawful processing.
   - Docker Compose mounts the named `portfolio-state` volume at `/app/var`, providing persistent local state across container recreation. No managed cloud storage is implied.

4. Optional untrusted public and external-provider boundary: controls are built, but no live public-company result is claimed.
   - The external path is constructed only for a public case with a reviewed Companies House number, both explicit runtime flags, an API key, and a named reviewer.
   - OpenAI Responses web search may propose bounded HTTPS URL candidates. Search snippets and free-form model prose are not evidence.
   - Guarded capture checks HTTPS, public addresses, redirects, robots, MIME, time, and byte limits. An optional model route receives only admitted public content with `store=False`; exact-span/schema checks remain mandatory.
   - Only admitted captured bytes and validated exact spans may return towards typed claims. Missing, blocked, failed, conflicting, or unsupported states remain visible.
   - The repository has fake, synthetic, and adversarial test evidence for this path. It does not provide a completed live public-company run, live-result quality evidence, or production SSRF assurance.
   - Direct Companies House and UKRI live registry adapters remain held under G2. Their synthetic replay and connector mechanics do not grant live permission.

5. Explicit non-goals / stop conditions.
   - Remote exposure; multi-user authentication, authorisation, tenancy, or concurrent production use; cloud deployment or managed storage; autonomous publication; production-security assurance; unrestricted crawling; person profiling; investment advice; and any statement that live public-company calls were completed are outside the demonstrated system boundary.
   - Named approval remains required before controlled report/export access; the verifier and composer cannot publish autonomously.
