\section{Engineering validation}

The final engineering run used the full automated test set. All 286 tests passed and executed
85.58~per cent of the source statements. Ruff found no lint errors, and strict MyPy found no type
errors across 46 source files. A new SQLite database applied migrations 0001--0009 and reported 0009
as the snapshot version \citep{pineau2021reproducibility,nist2023airmf}.

The formatting check failed. Ruff found five files that it would change. The dated snapshot retained
those five findings. The test run also produced 22 warnings about features that Starlette and the
SQLite date and time adapters may remove. Table~\ref{tab:eval-engineering-validation}, in
Appendix~\ref{app:reproducibility-build}, therefore reports a mixed result
\citep{gebru2021datasheets,pineau2021reproducibility}. The suite covers migrations, identity, time,
source policy, verification, review, export, research tasks and unsafe-network controls, all using
fictional data, fake providers and local files.

Coverage of 85.58 per cent counts source statements that ran, which is a weaker guarantee than
covering every requirement, branch or fault. Browser usability, concurrent users, backup recovery and
live sources were not tested at all \citep{hevner2004design,peffers2007dsrm,nist2023airmf}. The suite
does cover migrations, identity, time, source policy and records, verification, review, export,
research tasks and unsafe-network controls. That is artefact evidence for RQ1's preservation
question: the required records and stops exist in the evaluated version. It is not a coverage
figure for live sources, concurrent users or assistive-technology use, and it is not a substitute
for the D0 admission comparison in the next section.
Section~\ref{sec:limitations} states the binding limits once
\citep{hevner2004design,pineau2021reproducibility}.

\section{C1 versus C2}

D0 contains fourteen labelled fictional cases, accepted through a versioned evaluation record. C1 and
C2 use the same cases, data catalogue, cleaning rules and proposed values. C1 produces every eligible
cleaned value unless the company identity is unclear. C2 produces only values that a separate, fixed
verifier marks as supported. The saved evaluator output labels these conditions
\texttt{deterministic\_single\_agent} and \texttt{multi\_agent\_verification}. This dissertation
renames both, because the one change is the verification gate rather than the number of agents
\citep{guo2024multiagent,wu2024autogen,fu2026agents}. Each condition ran three times. The first run
was scored. Table~\ref{tab:eval-d0-comparison-design} makes the one change clear.

One feature of this design needs stating before any result is read. The expected outputs and
verification states live in the same visible development file that informed the rules, so D0 tests
programmed gates against cases written alongside them. It carries no event-link labels, no human
reference and no workload measures, which is why several rows in the results are null rather than
zero \citep{kapoor2023leakage,pineau2021reproducibility,peffers2007dsrm}.

The repeated run produced fourteen scored cases for each automated condition. C1 produced eleven
claims: five correct positive claims and six incorrect positive claims, with no required claim
missing. C2 produced five claims, all correct, and returned no claim for the other nine cases as
intended. C1 therefore had precision of 0.455, recall of 1.000 and F1 of 0.625. C2 recorded 1.000 for
all three measures. This change comes from blocking the six candidates designed to be unsupported
\citep{gao2023alce,gao2023rarr}.

The unsupported-claim rate fell from 0.545 in C1 to 0.000 in C2, while the supported-claim rate rose
from 0.455 to 1.000. Complete source records rose from 0.818 to 1.000 because two C1 claims did not
have every required source detail and C2 did not produce them. All three rates use the number of
claims produced as their total, and that total falls from eleven to five. The result therefore shows
more selective output, not wider source discovery \citep{gao2023alce,gebru2021datasheets}.

Both conditions followed the schema correctly, cleaned every value correctly and produced exactly
the same outcomes across the three repeats. C1 was correct in 0.571 of verification and no-claim
decisions, compared with 1.000 for C2. C1 missed both labelled contradictions and C2 found both, so
their contradiction scores were 0.000 and 1.000 on two cases.
Table~\ref{tab:eval-d0-results} keeps those values without combining them into one score
\citep{nikiforova2020quality,pineau2021reproducibility}.

Mean time was recorded as zero milliseconds for both conditions because the evaluator cuts times
below one millisecond down to the nearest whole number. The recorded LLM cost was USD~0 because both
routes are fixed and run locally. Measures for identity, extraction, event links and reviewer value
were blank because D0 has no suitable labels \citep{gebru2021datasheets,nist2023airmf}. Keeping a
blank result instead of changing it to zero avoids suggesting a measured failure or success. Identity
holds, extraction from new prose, live source quality and reviewer value remain unlabelled cells in
this fixture, not zeros that could be misread as perfect scores
\citep{nikiforova2020quality,gebru2021datasheets}.

\section{Case-level results}

C1 incorrectly produced claims for the conflict, old evidence, unsupported evidence, inaccessible
source, mixed currency and prompt injection cases. C2 refused admission of those six and kept the
complete case, the true zero, mixed data types, matching repeated evidence and claims supported by
prose. Section~\ref{sec:claim-journey} follows the observed-zero and the grant contradiction through
the eight stages. Table~\ref{tab:eval-d0-case-examples} records the fixture locators
\citep{gao2023rarr,bradley2024synfintabs}. Those two cases are the ones an investment team would
recognise without any metric vocabulary: a zero that must stay in the pack, and a grant figure that
must not be averaged against a register. The remaining four C1 false positives are the same
kind of silence: refusals of claim admission, not edits that make the sentence look better
\citep{gao2023alce,yue2023attrscore}. Section~\ref{sec:limitations} states the binding limits
once.

These results answer RQ2 for the conditions tested. The separately recorded verification stage
changed claim admission: it rejected every candidate D0 designed to be unsupported, conflicting,
stale, inaccessible, mixed-currency or injected, kept all five designed to be supported, and raised
source-record completeness by producing fewer claims rather than better-sourced ones
\citep{gao2023alce,peffers2007dsrm}.

The perfect C2 scores invite a comparison that should not be made. On SummExecEdit the best model
reached a joint detect-and-explain score of 0.49, and 60 inconsistent summaries were missed by every
model tested \citep{thorat2024summexecedit,kamoi2024realmistake}. C2 scored 1.000 on fourteen cases.
Those figures are not comparable. Thorat and colleagues evaluate held-out injected errors. D0 cases
were written beside the rules they test, which is the known risk of a checklist written by the same
hand that wrote the system \citep{ribeiro2020checklist,kapoor2023leakage}. The 1.000 records a
programmed gate on its own fixture. It is not a field detection rate.

Schema and normalisation accuracy were 1.000 in both conditions. Verification and abstention
accuracy were 0.571 for C1 and 1.000 for C2. Limits on reading those rates as a field or
population result sit in Section~\ref{sec:limitations}
\citep{nikiforova2020quality,pineau2021reproducibility}.

\section{Company-research and adversarial}

A dated focused run of the company-research, fixture and migration tests (28~August snapshot)
passed. The controlled end-to-end case
resolved a reviewed company number, admitted bounded search suggestions, accepted exact supporting
passages, composed a profile and required named review before download
\citep{gao2023alce,nist2023airmf}. Hostile-input tests rejected credential-bearing or non-HTTPS URLs,
blocked ports, private or changed network addresses, excessive redirects, robots exclusions, wrong
file types and oversized responses \citep{greshake2023indirect,autio2024genai}.

Table~\ref{tab:eval-company-adversarial-results}, in Appendix~\ref{app:supplementary-evaluation},
maps each control group to residual risk. This test run contacted no OpenAI, Companies House,
publisher or open website endpoint. Delay, tokens, cost, paywalls and open-web coverage remain
unmeasured \citep{openai2026websearch,pineau2021reproducibility}. Each pass means one specified input
was refused as designed.

Downloaded text remained untrusted. Suggested URLs had to appear in the bounded source list, retries
consumed the run budget, and exact captured passages supported accepted values. Tests also covered
publisher diversity, duplicate snapshots, identity passages, timeout failure, zero redirects and
run-specific cleanup. Inputs were local fixtures, fake providers or controlled responses, with one
Starlette deprecation warning \citep{greshake2023indirect,nist2023airmf}.
Section~\ref{sec:limitations} states the binding limits once.

The public-company source-discovery study, the manual baseline C0 and the participant-review
condition C3 produced nothing to report. Each needed frozen companies, reference labels and stopping
rules agreed before collection. A comparison arranged after the data are seen cannot demonstrate
equal information access \citep{kapoor2023leakage,pineau2021reproducibility,bucinca2021forcing}.
Tables~\ref{tab:eval-held-company-comparison} and \ref{tab:eval-human-comparison-status}, in
Appendix~\ref{app:supplementary-evaluation}, distinguish those absent comparisons from executed
results.

A caution applies to all of the security results. Each is a stated example, and a pass means one
specified input was refused as designed. Estimating resistance beyond these examples would need
generated inputs, dependency checks and penetration testing designed by someone else
\citep{greshake2023indirect,nist2023airmf}. The company-research route passed controlled tests but
has never been run against a live company, a live public website or an external model.
Section~\ref{sec:limitations} states the binding limits once
\citep{openai2026websearch,pineau2021reproducibility}.

\section{Negative, null and unavailable}

Negative results were kept. Ruff's formatting check failed for five files. C1 produced six incorrect
positive claims and missed both labelled contradictions. Timings of zero milliseconds gave no useful
speed comparison \citep{pineau2021reproducibility,nist2023airmf}.

Where D0 has no label and where a condition never ran, the result field stays empty. The distinct
reasons for absence -- a blocked request, an unavailable source, no record, an unsupported claim, a
contradiction and an outright failure -- are never merged into one
\citep{gebru2021datasheets,gao2023rarr}. The null cells are not interchangeable. Identity-hold
accuracy is null because D0 contains no labelled identity conflict scored as an identity metric.
Extraction from new prose is null because the fixture's narrative case is already labelled.
Reviewer value is null because no participant sat in front of the screen. Cost is a recorded
zero, which is a different fact: the measure ran and the local rules incurred no model charge
\citep{nikiforova2020quality,nist2023airmf}. The unrun comparisons classified in
Table~\ref{tab:meth-evidence-scope} are absent rather than weak. Section~\ref{sec:limitations}
states the binding limits once.
