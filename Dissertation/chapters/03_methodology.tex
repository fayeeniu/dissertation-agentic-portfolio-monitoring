\chapter{Research Design and Methodology}
\section{Applied design-science strategy}

This dissertation uses an applied design-science strategy because the research object is a working
portfolio-reporting artefact for a bounded organisational problem. Design science links construction
to evaluation against stated objectives \citep{hevner2004design,peffers2007dsrm}. The method therefore
separates three kinds of evidence: implementation records show what was built, engineering tests show
which specified behaviours were exercised, and D0 shows how two workflow conditions handled labelled
fictional cases. None of these observations is treated as evidence of business benefit.

The student built and evaluated the artefact, which creates confirmation risk. The main controls were
fixed case labels and metrics, versioned code and fixtures, saved result files, complete failure
accounting and repeated runs. Reproducibility requires enough code, data, procedure and reporting
detail for another person to inspect the route to a result
\citep{pineau2021reproducibility,nist2023airmf}. These
controls make changes visible, but they do not provide independent validation.

Figure~\ref{fig:meth-design-science-evidence-chain} shows the evidence boundary used throughout the
study. Manual work, participant review, live-web operation and managed-platform comparison were
removed from the active research questions because they had no authorised observations. Their
protocols are retained only as future evaluation material. This keeps unobserved outcomes null rather
than converting an evaluation plan into a result \citep{nist2023airmf,hevner2004design}.

\section{Evaluand and comparison conditions}

The evaluand is the complete local workflow configuration: input rules, catalogue, source access,
operational roles, verification, prompts, schemas, computing environment and stop conditions. This
binds each observation to one defined artefact version. Design-science evaluation requires comparison
with stated objectives \citep{hevner2004design,peffers2007dsrm}, while system reporting should state
the intended use, version and evaluation procedure \citep{mitchell2019modelcards}.

The executed comparison uses C1 and C2. C1 applies the shared catalogue and normalisation rules and
emits each eligible cleaned value unless identity is unclear. It retains available provenance but has
no separately recorded verifier. C2 receives the same candidate values and evidence, then admits a
claim only when the separate fixed verifier marks it as supported. Composition cannot override that
decision. Each condition ran three times on the same fourteen D0 cases, so the measured difference is
the verification gate and its recorded decision, not a claim about agent personalities
\citep{guo2024multiagent,wu2024autogen}.

The original protocol also defined C0 manual work and C3 named review. These conditions did not run
and are not used to answer RQ1 or RQ2. Their detailed condition matrix is kept as
Table~\ref{tab:meth-condition-matrix} in Appendix~\ref{app:dataset-source-freeze} to support a future authorised pilot. Retaining the protocol
preserves the planned comparison without presenting missing observations as evidence
\citep{pineau2021reproducibility,nist2023airmf}.

\section{D0 fixture, labels and freeze}

D0 contains fourteen visible, labelled fictional cases designed to expose known error categories.
They cover complete and sparse records, blank and observed-zero values, mixed types, conflicting and
stale evidence, unsupported and inaccessible sources, unclear identity, duplicate support, narrative
evidence, mixed currencies and prompt injection. This one-case-per-category structure is deliberate
and follows the behavioural-testing argument set out in Section 2.7: a suite of targeted cases, each
probing one specified behaviour, reveals failures that an aggregate score over a single test set hides
\citep{ribeiro2020checklist}. Synthetic material serves that purpose well because it supplies
controlled labels, provided its construction and permitted use are explicit
\citep{bradley2024synfintabs,gebru2021datasheets}.

The fixture and its evaluation record are checksum-pinned. Loading checks the schema version, data
classification, source version, file checksum and test-only namespace. Case and evidence identifiers
are placed in a benchmark namespace that the operational collector rejects. The labels specify the
expected emission decision and verification status. The complete case ledger is
Table~\ref{tab:appendix-d0-case-ledger} in Appendix~\ref{app:supplementary-evaluation}
\citep{gebru2021datasheets,pineau2021reproducibility}.

D0 is a development fixture, not a sample of companies. The rules and cases were developed together,
so the result establishes only whether the programmed gate behaves as designed on these cases. A
future pilot must create independent labels before a sealed final set is opened. Separating
development from final evaluation reduces leakage risk \citep{kapoor2023leakage}, and versioned data
records support later repetition \citep{pineau2021reproducibility,mitchell2019modelcards}.

\section{Source parity and reference decisions}

For D0, both conditions receive the same candidate value, evidence record, reporting period and
precondition. Scoring uses the fixture's expected emission and status fields. The evaluator does not
give either condition later evidence or a wider source window. This equal-input design is sufficient
for the narrow C1/C2 mechanism comparison, but the visible development labels are not an independent
reference \citep{kapoor2023leakage,pineau2021reproducibility}.

A real-company evaluation would require an eligible-source list, cut-off date, independently labelled
claims and recorded adjudication. Agreement would indicate consistency rather than truth because
reviewers can share an error \citep{artstein2008agreement}. Exact locators and source records would
also remain necessary because citation presence does not establish complete or correct support
\citep{gao2023alce,pineau2021reproducibility}. The full prospective reference-parity matrix is
Table~\ref{tab:meth-reference-parity-matrix} in Appendix~\ref{app:dataset-source-freeze}.

\section{Measures and denominator rules}

The primary D0 measures are supported-claim precision, recall, F1, unsupported-claim rate,
supported-claim rate, source-record completeness, verification or abstention accuracy,
contradiction accuracy and exact repeat consistency. Precision uses supported emitted claims over all
emitted claims. Recall uses correctly emitted required claims over all required claims. Unsupported
claim rate uses unsupported emitted claims over all emitted claims. These denominators keep claim
correctness separate from citation presence and support \citep{gao2023alce,gao2023rarr}.

Schema and normalisation accuracy are also reported because both conditions share earlier processing.
Contradiction accuracy has two applicable cases and is interpreted as a small case result, not a stable rate.
Duration values below one millisecond were truncated to zero, so they cannot support a speed
comparison. Model cost is zero because D0 uses fixed local rules. Measures without D0 labels remain
null, not zero. Clear missing states and denominators are necessary for task-specific data-quality
interpretation \citep{nikiforova2020quality,gebru2021datasheets}.

The complete metric and denominator matrix in Appendix~\ref{app:supplementary-evaluation} also defines
prospective human time, edit, usability, source-coverage and cost measures. Those fields are pilot
metrics, not results of this study \citep{gale2013framework,nist2023airmf}.

\section{Analysis and interpretation}

The evaluator reports counts before rates and keeps all fourteen paired cases in both conditions.
The first repeat supplies the scored values, and the complete ordered result list is compared across
all three repeats. Individual cases explain why an aggregate changed. No confidence interval or
hypothesis test is reported because D0 is a small, deliberately constructed fixture rather than a
sample drawn from a target population \citep{demsar2006comparisons,diciccio1996bootstrap}.

Error analysis uses the expected verification states and records false emission, false withholding,
conflict, stale evidence, inaccessible evidence, identity hold and untrusted content separately.
Negative and unavailable outcomes remain in the record. Any later study should pair the same
company-periods, report exclusions before rates and use uncertainty at the company or report level,
not treat repeated fields as independent observations \citep{kapoor2023leakage,pineau2021reproducibility}.

\section{Ethics, leakage prevention and reproducibility}

Every input is classified as restricted, internal, public or synthetic. Restricted material remains
local, and public availability does not itself authorise every use. Participant observation and live
external processing require separate authority, purpose, consent and storage decisions
\citep{gebru2021datasheets,cddo2023genai,nist2023airmf}. D0 uses only fictional data and no external
source or model call.

The evaluation record retains the Git revision and dirty-state warning, platform and dependency
versions, migration version, fixture and protocol checksums, test commands, result files, failures and
output hashes. A checksum detects byte changes but cannot establish truth or independent replication
\citep{pineau2021reproducibility,mitchell2019modelcards}. The detailed implementation snapshot is in
Appendix~\ref{app:reproducibility-build}.

Collection or evaluation must stop when authority is unclear, a credential is exposed, unexpected
personal data appears, source terms would be breached, restricted data would reach an unapproved
service, or a sealed evaluation set is compromised. The detailed evidence-control matrix is retained
in Appendix~\ref{app:source-provider-controls}. These controls define the research boundary; they do
not imply ethics approval for the future pilot \citep{nist2023airmf,pineau2021reproducibility}.
